- **End-to-end tests (spec 90.3):** the Playwright suite in `apps/web/e2e` runs against an isolated production build with its own throwaway database (`pnpm test:e2e:isolated`, README "Testing end to end"). Result of two runs in a row on 2026-10-04: 65 passed, 3 skipped, 0 failed, 0 expected failures in each run. The 3 skipped tests are `recorder.spec.ts`, which needs `/dev/recorder` and therefore a development server (`pnpm test:e2e`).
- **Defects found by the end-to-end suite, all fixed with a unit or service test each:**
  - E2E-1: every ZIP export failed with the local storage driver, and a failed export could keep its worker slot forever. The storage drivers now accept any Node-style readable stream and any async iterable of bytes through one helper (`packages/storage/src/body.ts`), and every failure of the archive, of a source stream or of the upload ends the export as `failed` (`packages/research/src/exports/package.ts`). Tests: `packages/storage/src/testing/adapterContract.ts` (run by all three drivers), `packages/research/src/exports/local-storage.test.ts`.
  - E2E-2: the missing API key was reported as a generic failure. Cause: the production web build holds several copies of the error classes, while the provider registry lives once per process, so `instanceof AppError` was false for its errors. `isAppError`, `isAiProviderError` and `isRetryableAiError` now check the shape of the error. Tests: `packages/domain/src/errors.test.ts`, `packages/ai/src/errors.test.ts`, `packages/research/src/demo/demo.test.ts`.
  - E2E-3: redirect loop between `/admin` and `/admin/login` for a cookie issued before a sign-out elsewhere. `apps/web/proxy.ts` no longer redirects away from the login page; the login page decides with the full session check. A refused cookie is removed by the proxy (when it fails the proxy check) or on request of the login page (`POST /api/admin/logout?rejected-cookie-only=1`), because a page cannot change cookies while it renders. Tests: `apps/web/proxy.test.ts`, `apps/web/app/api/admin/login/route.test.ts`, `apps/web/app/admin/login/LoginForm.test.tsx`.
  - E2E-4: "Delete TEST and DEMO data" left queue jobs without a batch behind. The reset (and the purge of one demo session) now removes the jobs whose payload names a deleted utterance or media file, and never a job of research data. Tests: `packages/db/src/invariants.test.ts`, `packages/research/src/demo/demo.test.ts`.
- **Production checks on the rebuilt web image (2026-10-04):** `scripts/check-production-csp.mjs` passes without `CHECK_TOLERATE_BLOCKED_EVAL`, and the web container started without `ADMIN_SESSION_SECRET` prints the variable name and exits with code 1 (`docs/DEPLOYMENT.md`, sections 4 and 9).

### What does not work (do not retry)

- Two `next dev` servers in `apps/web` at once: Next.js allows one per directory. End-to-end tests that change global state run on the isolated stack (`pnpm test:e2e:isolated`), not on the dev server.
- `instanceof` checks on the project's own error classes across packages: the production web bundle holds several copies of each class. Use `isAppError`, `isAiProviderError` and the other structural helpers.
- Passing a ZIP archive stream to storage with an `instanceof Readable` check: the archiver stream comes from another stream library. `packages/storage/src/body.ts` (`toNodeReadable`) handles it.
- Routing an upload through `apps/web/proxy.ts`: Next.js cuts proxied request bodies at 10 MB.
- Changing published seed content on an existing database: published rows are immutable and the seed only adds missing records. Use a new database.
- Tests of the storage layer with the in-memory driver only: it accepted streams the local driver rejected. `packages/research/src/exports/local-storage.test.ts` covers the real driver.

### Known open items

Demo recordings follow the study settings (`maxUtteranceSeconds`, `maxUploadMb`); a pipeline test clip is at most 30 seconds (`docs/DEMO-MODE.md`, "Limits").
   - The seed sets `store: false` in the translation model configs (new databases only). An existing database keeps its configs: add the parameter in a new config version on the AI Pipeline page. What the provider retains otherwise depends on the account (privacy review item).

The seed only adds missing records and published rows never change, so this reaches new databases only: the development database still shows the old questionnaire descriptions ("Placeholder background questions (spec 11)").
